# Draft-Ready Writing Support

## Problem Statement

This project develops a next-day decision-support system for a bike-share operations planning manager using the Capital Bikeshare hourly demand dataset. The operational challenge is to set hourly availability targets that reduce shortage risk without creating excessive idle inventory, while also translating those demand expectations into actionable overnight repositioning recommendations. Because the dataset provides system-level hourly rentals and weather conditions rather than station-level inventories or trip flows, the project combines an empirically grounded forecasting and capacity-planning layer with a transparent, manager-configurable zone rebalancing prototype. The resulting workflow supports practical operating decisions while remaining explicit about what the data can and cannot justify.

## Abstract

Bike-share systems must balance two competing operational risks: failing to meet demand during peak periods and holding too many idle bikes during weaker periods. This project builds an integrated predictive and prescriptive analytics pipeline using the public Capital Bikeshare hourly dataset to support next-day operations planning. The analysis begins with data validation and anomaly review, followed by descriptive analytics of temporal and weather-driven demand patterns. Multiple forecasting models are then compared in a rolling time-aware validation framework to predict hourly bike demand for the following day. Forecast outputs feed a critical-fractile availability planning model that sets cost-sensitive hourly service targets, and a stylized overnight zone rebalancing model translates those targets into actionable bike-movement recommendations under aggregate-data constraints. Scenario analysis evaluates sensitivity to weather, cost assumptions, available fleet size, and commuter surges, and the final outputs are delivered through a Streamlit dashboard designed for operations managers. The project demonstrates how forecasting and optimization can be integrated into a practical management-engineering decision-support system without overstating what the available data can support.

## Executive Summary

The project shows that the bike-sharing dataset can support a strong next-day operations planning system when forecasting and optimization are treated as one integrated pipeline instead of separate analyses. Hourly demand is shaped most strongly by time-of-day, workingday patterns, seasonality, and weather, with clear commute peaks on working days and broader midday peaks on weekends and holidays. A time-aware forecasting workflow provides materially better operational guidance than a naive historical baseline, and those forecasts become useful only when converted into decisions. To do that, the project uses a cost-based availability policy to balance shortage risk against idle inventory and then applies a transparent overnight zone rebalancing prototype that recommends how bikes should be shifted across Residential, Employment Core, and Leisure/Mixed Use operating areas. The result is a realistic decision-support workflow that improves service-oriented planning while staying honest about the aggregate nature of the data.

## Recommendations

The operations team should adopt a forecast-driven next-day planning process rather than relying on a static average hourly profile. In practice, that means generating end-of-day hourly demand forecasts, converting them into availability targets using explicit shortage and idle cost assumptions, and using those targets to guide overnight repositioning into high-priority operating zones. Working-day plans should emphasize early-morning and evening commute periods, especially in Residential and Employment Core zones, while weekend plans should shift more inventory toward Leisure/Mixed Use demand. Managers should also use the scenario module regularly to stress-test plans against bad weather, lower fleet availability, and higher shortage penalties before finalizing overnight actions.

## Limitations

The project uses an aggregate hourly dataset, so it cannot directly estimate station-level inventories, route-level movement flows, or true unmet demand. As a result, the rebalancing model is intentionally framed as a zone-based operational prototype rather than a literal station-to-station routing solution. Weather inputs in backtesting are treated as known next-day conditions, which is appropriate for benchmarking but optimistic relative to real deployment. Cost and business-impact outputs should therefore be interpreted primarily as decision-support proxies unless the operator can provide internal cost, inventory, and service-failure data for calibration.

## Conclusion

This project demonstrates that a public bike-sharing dataset can support a coherent Management Engineering pipeline when predictive and prescriptive analytics are tightly integrated and carefully scoped. The forecasting layer captures operationally important demand variation, the availability-planning layer converts predictions into service targets, and the zone rebalancing layer shows how those targets can inform overnight action under realistic data limitations. The final system is useful not because it claims impossible spatial precision, but because it makes transparent, defensible recommendations that an operations manager could adapt as richer inventory and station data become available.
